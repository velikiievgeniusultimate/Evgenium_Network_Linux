# CLI на Debian/RISC-V

Поддерживается Debian 13 riscv64 (RV64GC, например StarFive VisionFive 2).
CLI написан на Python 3; машинные компоненты — официальный Xray 26.7.28 для riscv64
и закреплённый EvgeniumTunnel 0.3.0 riscv64. SHA-256 обоих компонентов проверяется.
Токены, приватные ключи и сертификаты не входят в релиз и создаются отдельно.

## Установка

От обычного пользователя, с sudo в своём терминале:

```bash
curl -fsSL https://raw.githubusercontent.com/velikiievgeniusultimate/Evgenium_Network_Linux/main/install.sh -o install.sh
bash install.sh --cli-only
vpn token save
vpn device name STARFIVE
vpn mode include
vpn include app add codex
vpn on
```

Токен вводится скрыто, без аргументов командной строки. `--cli-only` сохраняется
в настройках, поэтому `vpn update` не установит Qt, GUI или виджет. Установка
сохраняет резервную копию прежних настроек. VPN не включается самой установкой.
Команды выше для main доступны после включения изменений 0.6.2 в основную ветку.

Для автономного установочного пакета из проверенного checkout:

```bash
python3 scripts/build_release.py --channels stable testing
bash install.sh --cli-only --release-file="$PWD/dist/vpn-manager-0.6.2.tar.gz"
```

Рядом должен находиться `vpn-manager-0.6.2.tar.gz.sha256`. Архив проверяется до
установки, разрешены только vpnctl.py, vpnadmin.py и VERSION. Машинные зависимости
получаются отдельно из официальных Debian/GitHub-источников с проверкой SHA-256.
Полная установка меняет системные маршруты и требует root; сам CLI нельзя
проверять полноценным `vpn on` от непривилегированного пользователя.

## Включительный режим

```bash
vpn mode include
vpn include app add codex
vpn include app add /opt/my-app/bin/my-app
vpn include site add openai.com
vpn include site add =exact.example.com
vpn include site add 203.0.113.10/32
vpn include port add tcp:443:out
vpn include dns add 1.1.1.1
vpn include app list
vpn include site remove =exact.example.com
vpn rules
vpn status --ip
```

Добавляйте только нужные правила: примеры не являются обязательным набором.
`vpn status --ip` специально проверяет VPN-выход. Внешний IP невыбранного `curl`
проверяется обычной командой, без SOCKS-прокси. При сбое системного DNS клиент сохраняет рабочий туннель и показывает предупреждение. Приложения, которым нужен системный DNS, могут временно не открывать сайты по имени. Правила app относятся к процессам,
которые создают соединения: помощники и дочерние программы могут требовать своих
правил. У Codex сетевые запросы к OpenAI выполняются процессом codex.

Приоритеты: ответы входящих соединений и действующие DIRECT-исключения/локальные
сети, затем выбранные исходящие приложения/сайты/порты, затем DIRECT. Порты в
списке include относятся только к исходящим соединениям (`:out`; это же значение
по умолчанию без направления). Системный DNS сохраняет исходный путь, если его
сервер не выбран отдельно. Выбор приложения сам по себе не меняет общий системный
DNS. Проверочные внутренние запросы VPN всегда идут через VPN.

При потере транспорта список VPN остаётся закрытым, а классификатор продолжает
передавать невыбранное напрямую. Если упал сам классификатор, отличить выбранное
от невыбранного невозможно: неклассифицированный трафик блокируется до его
восстановления. Явная команда `vpn off` возвращает обычную сеть для всего.

IPv6 в текущем движке не маршрутизируется через VPN и под защитой блокируется.
Домен определяется по HTTP/TLS/QUIC. При ECH, неизвестном протоколе или отсутствии
видимого имени используйте правило приложения/IP; скрытый домен сам по себе не
гарантирует выбор маршрута. Входящие SSH/HTTP-ответы идут напрямую, чтобы сервер
сохранял доступность по своему российскому адресу.

`vpn mode all` включает прежнюю модель. DIRECT-списки (`vpn app`, `vpn direct`,
`vpn port`, `vpn dns`) и include-списки хранятся отдельно и переживают переключение,
обновление и восстановление. Существующая установка автоматически не меняет режим.

## Проверки

```bash
python3 -m unittest discover -s tests -v
sudo python3 scripts/test-upgrade-sandbox.py
sudo env EVG_TEST_XRAY=/opt/vpn-manager/bin/xray python3 scripts/test-unified-policy.py
```

Сетевые проверки создают отдельные namespaces и локальные тестовые DIRECT/VPN-
сервера. Они проверяют фактический маршрут приложений, доменов, IP, портов и DNS,
ответы входящего сервера, потерю VPN и потерю классификатора. Они не меняют рабочий
VPN или SSH хоста. На реальном StarFive дополнительно проверены запуск официального
Xray riscv64 и самопроверка пакета CLI; включение боевого VPN требует установки и
отдельной проверки на плате.

## Панический поиск VPN (0.6.1)

`vpn panic on` сохраняет режим, включает VPN и его запуск при загрузке сервера.
Если подготовка не удалась, она повторяется без ограничения попыток (паузы
5–30 секунд). При потере рабочего соединения клиент перебирает все известные
маршруты по кругу, даже если ранее был выбран один маршрут вручную. Сохранённый
ручной выбор не меняется; обычный режим снова его учитывает. В паническом режиме
начальная проверка скорости всех маршрутов пропускается: сначала восстанавливается
связь. Во время работы здоровье проверяется примерно каждые 2 секунды, плюс время
сетевых проверок; два подряд сбоя запускают переключение. Между попытками маршрута
пауза 1 секунда (при отсутствии физической сети — 3 секунды).

systemd перезапускает упавший процесс без ограничения числа перезапусков с паузой
5 секунд. Это не гарантирует соединение, когда все серверы или сама сеть недоступны.
Режим include и списки VPN/DIRECT сохраняются; восстановление не переводит весь
трафик в VPN. Работающий маршрут не переключается только ради повторного поиска.

- `vpn panic status` — состояние режима; оно также видно в `vpn status`.
- `vpn panic off` — обычное восстановление, без автозапуска; работающий VPN остаётся включённым.
- `vpn off` — остановить VPN и отключить запуск при загрузке. Настройка panic
  сохраняется для следующего `vpn on`; явная остановка не отменяется watchdog.

Автозапуск настроен через systemd; перезагрузка сервера при установке не выполняется.
