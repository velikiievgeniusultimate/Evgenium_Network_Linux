# Панель владельца Evgenium Network

Панель и издатель сертификатов работают на HSVDS (Ubuntu 24.04). Публичный HTTPS идёт напрямую на HSVDS: DNS-запись A `195.209.211.163`, без проксирования Cloudflare. VPN и связь с Эстонией для открытия панели не нужны.

```text
https://panel.velikiievgenius.com
```

## Вход

Новый браузер требует пароль (14–256 символов, scrypt) и Google Authenticator. После успешного входа браузер автоматически запоминается на 30 дней; при следующем входе нужен свежий код Authenticator. Пароль не сохраняется в браузере: отдельный случайный 256-битный ключ хранится в Secure/HttpOnly/SameSite=Strict cookie, в SQLite — только его SHA256. При успешном входе ключ заменяется, старый отзывается. Сам ключ без кода не открывает панель. Повторное использование кода отклоняется глобально, включая другие браузеры.

«Выйти» завершает сеанс, сохраняя доверие браузеру. «Забыть этот браузер» отзывает его ключ и завершает сеанс; после этого нужны пароль и код. На чужом компьютере используйте именно «Забыть этот браузер». После очистки cookie или истечения 30 дней также требуется пароль. Сервер хранит не более 50 действующих ключей браузеров.

Сессия ограничена 8 часами и 30 минутами отсутствия запросов. Открытая панель обновляет данные раз в 30 секунд. Сохраняются CSRF, Origin/Host проверки, ограничения попыток входа и запрет кеширования. TOTP зашифрован; QR не отправляется сторонним сервисам. Восстановление утраченного Authenticator требует администратора через SSH.

## Пользователи, токены и устройства

- Один пользователь — один токен, до 12 устройств. Дубли имён после нормализации запрещены.
- «Переименовать токен» меняет имя карточки пользователя и токена; сам токен, сертификаты и подключения сохраняются.
- У устройства есть собственное имя. Оно редактируется в панели или клиенте. По умолчанию «Устройство-1», «Устройство-2» и далее отдельно для каждого пользователя. Клиент получает имя с сервера при подключении, подтверждении токена или `vpn device sync`.
- «Удалить пользователя» требует подтверждения с именем. Издатель сначала блокирует токен, затем отзывает все поколения сертификатов пользователя, загружает CRL и отключает только его IKE-сессии. Другие VPN-сессии и strongSwan не перезапускаются. Службы HTTPS диагностики перезапускаются для загрузки CRL.
- При ошибке удаляемый пользователь остаётся видимым с отметкой незавершённого удаления; выдача новых сертификатов уже отключена. Повторная попытка безопасно завершает отзыв. Не считать ошибку успешным удалением.
- После завершения карточка исчезает, зашифрованная копия токена удаляется. В закрытой базе остаётся запись об отзыве, в CA — история сертификатов. Повторное создание пользователя выдаёт новый токен.
- Токены зашифрованы в root-хранилище, раскрываются только владельцу. Для старых токенов, сохранённых ранее только как хеш, нужен импорт существующей копии.

Панель показывает службы, ресурсы, последние измерения канала и подключения strongSwan. Недоступное измерение обозначается как неизвестное. История падений пока не реализована. Журнал содержит операции без паролей, кодов или токенов.

## Установка и обновление

Сначала установите актуальные `server/token_issuer.py` и `server/diagnostic_collector.py` в существующие службы выдачи. Публичный collector разрешает только `/enroll` и `/device`, принудительно задаёт операцию и не передаёт публичные административные команды. Удаление доступно лишь через root Unix socket issuer; веб-приложение обращается к узкому брокеру под отдельным UID.

```bash
sudo bash server/panel/install.sh
```

Установщик автоматически ставит Flask, Gunicorn, cryptography, qrcode. Повторная установка сохраняет владельца, TOTP, пользователей и ключи. Для отзыва issuer получает право записи только в дополнительный каталог `/etc/swanctl/x509crl`. Перезапускаются issuer и две службы панели; маршруты, firewall и strongSwan не меняются.

Панель слушает `127.0.0.1:9081` и Unix socket `/var/lib/evgenium-panel-http/panel.sock`. Разрешённый домен задаётся `allowed_hosts` в `/etc/evgenium-panel/config.json`. Первичная настройка нового сервера использует root-only `/root/evgenium-panel-bootstrap.txt` в течение 24 часов. Не сбрасывайте владельца при обновлении.

Прямой HTTPS обслуживает общий HAProxy из `server/connect/infra`: SNI панели
выбирает отдельный TLS frontend на loopback 9445, затем Gunicorn 9081. Публичный
HTTP 80 перенаправляет на HTTPS. Перед включением этой конфигурации нужны оба
действительных PEM: `/etc/evgenium-connect/tls.pem` и `/etc/evgenium-panel/tls.pem`.
Сертификат панели — Certbot lineage `evgenium-panel-direct`; автопродление через
HTTP webroot `/var/lib/evgenium-connect-acme`. Общий deploy hook обновляет только
нужный PEM и плавно перезагружает HAProxy. Подробности в `server/connect/infra/OPERATIONS.md`.

Фронтенд принудительно задаёт `X-Forwarded-Proto: https` и реальный клиентский
`X-Forwarded-For`; приложение доверяет ровно одному прокси. Gunicorn должен
оставаться на loopback. Публичный порт 9081 или доверие произвольным заголовкам
клиента недопустимы. Host/Origin, CSRF, пароль/TOTP и запрет кеширования сохраняются.

Прежний Cloudflare connector оставлен для ручного отката и не используется
основной DNS-записью. Он работает в `evg-link`; не возвращайте его в основной
маршрут без решения владельца: тогда снова появится зависимость от Cloudflare
и межсерверного канала.

## Резервное копирование и проверки

Сохраняйте согласованные root-only копии `/etc/evgenium-panel`, `/var/lib/evgenium-panel` (SQLite backup API), `/var/lib/evgenium-panel-broker`, `/var/lib/evgenium-enrollment` (под accounts.lock), `/root/evgenium-ikev2-pki` (под ca.lock), `/etc/swanctl/x509crl`, конфигурации connector. Порядок блокировок: accounts, затем CA. Копии содержат секреты, их нельзя публиковать. Не восстанавливайте старую базу или CA поверх текущей: это может вернуть отозванный доступ.

```bash
python -m unittest discover -s server/panel/tests -v
python -m unittest discover -s tests -p test_account_revocation.py -v
```

Проверки отзыва используют временную CA и настоящие OpenSSL CRL; системные действия заменены тестовыми. Установленная панель проверяется без удаления действующих пользователей. При перезапуске брокера зависимая `evgenium-panel` может остановиться: после него обязательно запустите её снова.
