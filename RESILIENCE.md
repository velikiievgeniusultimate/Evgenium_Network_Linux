# Устойчивость и добровольные отчёты

Клиент проверяет три пути: российский вход с резервируемой связью в Эстонию,
прямой UDP-вход Эстонии, прямой TLS-вход Эстонии. При первом подключении и
`vpn repair` проверяет доступ, целостность, скорость приёма и отдачи и сохраняет
порядок. Короткий замер нужен для сравнения, а не для обещания максимальной скорости.
Обычный `vpn on` использует сохранённый порядок. Два последовательных сбоя
текущего пути дают один проигрыш и переключение; три проигрыша исключают путь
до нового `vpn repair`. Успешное подключение не обнуляет проигрыши.
Отключение кабеля не считается проигрышем транспорта.

Дополнительные восстановления:

1. Частный DNS внутри VPN с UDP, TCP и DoH. Если системный DNS перестал
   отвечать, клиент переключает файл резолвера на собственный защищённый DNS.
   При явном отключении возвращает прежнюю настройку; чужие последующие
   изменения не перезаписывает. Процесс частного DNS при падении перезапускается.
2. Текущий путь проверяется по внутреннему HTTPS и внешнему эстонскому адресу.
   При отказе — следующий путь с сохранением блокировки защищённого трафика.
   На сервере отдельные проверки пяти межсерверных транспортов позволяют
   перезапустить зависший резерв или переключить действующий канал.
3. Раз в примерно 10 минут при наличии трафика (от 4 МиБ за интервал) короткий
   замер по 2 МиБ в обе стороны проверяет скорость. На простаивающем VPN
   нагрузочные замеры не идут. Первичный и повторный замеры одного размера.
   Падение любого направления ниже 20% его исходного уровня (если исходно
   не менее 2 Мбит/с) проверяется ещё дважды через 20 секунд. Только три
   подтверждения дают проигрыш и переключение. Ошибка сервиса измерения
   сама по себе не считается падением скорости.
4. Старые соединения разрешённых приложений и локальной сети не уничтожаются
   массовой командой сброса сокетов. При смене публичного пути часть приложений
   всё равно должна переподключиться: нулевой потери пакетов система не обещает.

DNS идёт внутри VPN; явные пользовательские исключения остаются исключениями.
Служебный трафик до входа VPN необходим для установки защищённого соединения.

## Отчёт по согласию

GUI: «Отчёт для поддержки» → просмотр → отдельная отметка согласия → отправка.
CLI:

```sh
vpn report preview
vpn report send --consent --id ID_ИЗ_ПРЕДПРОСМОТРА
```

Первый шаг ничего не отправляет. Отчёт содержит версию/семейство ОС/архитектуру,
этапы и категории ошибок, пути и их замеры, счётчики собственного VPN-интерфейса
и IPsec. Нет токенов, ключей, паролей, посещённых сайтов, списка приложений или
содержимого пользовательского трафика. Сервер повторно фильтрует поля и связывает
отчёты с псевдонимом сертификата, а не IP или именем компьютера. Локально хранится
не более 128 переходов состояния. Предпросмотр действителен 24 часа.

Сервер: до 6 новых отчётов с сертификата в час, повторная отправка того же ID
не дублируется в пределах часа работы процесса, общий предел 32 МиБ/сутки,
хранение до 7 дней. Лимит частоты в памяти сбрасывается при перезапуске сервиса;
дисковый предел сохраняется. Отправка не создаёт исключение из kill switch:
при закрытой сети отчёт остаётся локально, после восстановления его можно отправить.

Владелец получает агрегат командой `support-summary` рядом с серверным сборщиком.
Сводка показывает версии, категории отказов и медианы скорости путей, без
идентификаторов устройств. Для массового анализа собирайте отчёты нескольких
пользователей в одно время и сравнивайте со временем серверных инцидентов.
Серверные кольцевые захваты ограничены по объёму и содержат только шифрованные
транспорты, не расшифрованный клиентский интерфейс.
