# Подписанные Android-сборки

Пакет для пользователей: `com.evgenium.network`. Лабораторный пакет:
`com.evgenium.network.lab`; он устанавливается отдельно и не используется как
канал обновлений пользователей. Перенос токена выполняется кнопкой в лабораторной
версии после проверки подписи установленного получателя. Пользователь подтверждает
перенос в обоих приложениях; создаётся отдельный сертификат устройства.

Сборка: Java 21, Android SDK 36/build-tools 36.0.0, NDK 27.3.13750724.
`ANDROID_HOME=<sdk> EVG_ANDROID_RELEASE=1 EVG_SIGNING_DIR=<private-directory> android/build.sh`
Подпись: PKCS12 `release.p12`, alias `evgenium`, пароль в `store-password.txt`.
Эти файлы никогда не входят в репозиторий или архив исходников.
Публичный сертификат: `release-certificate.der`.

Обновления проверяются вручную в настройках. Манифест содержит version_code,
размер, SHA-256 и HTTPS-ссылку на APK. До передачи установщику проверяются размер,
хеш, имя пакета, постоянная подпись и строго возрастающая версия. Разрешение
Android на установку APK запрашивает сама ОС. Повторная попытка после разрешения
использует сохранённый APK только после повторной проверки.

## Защита и восстановление

Для блокировки утечек при завершении процесса нужно включить **обе** системные
настройки: «Постоянный VPN» и «Блокировать соединения без VPN». Приложение не
может включить их вместо владельца обычным Android API. Без второй настройки
Android может вернуть прямой Интернет после смерти VPN-процесса. На отдельных
прошивках также нужно разрешить автозапуск/фоновую работу в настройках батареи.
Главный экран и настройки показывают состояние системной блокировки.

Системный запуск и обычная кнопка используют один Engine. Обычное отключение
снимает намерение автоматического подключения; отзыв VPN-разрешения прекращает
работу Engine. После перезапуска восстанавливается выбранный маршрут.

За семь дней до истечения сертификата клиент запрашивает обновление с тем же
ключом и идентификатором устройства. При временном сбое действующий сертификат
сохраняется, повторная попытка — через час. Просроченный сертификат не используется.
Регистрация использует фиксированный сервер, закреплённый CA и проверку имени TLS.
Под собственным VPN защищается только служебный сокет регистрации; при другом
работающем VPN первичная регистрация следует обычному маршруту этого VPN.
При утрате AndroidKeyStore надо заново подтвердить пользовательский токен:
новая установка получает новую идентичность, старое устройство следует отозвать.

## Выпуск

Публиковать APK вместе с архивом соответствующих исходников, SBOM и SHA256SUMS.
Архив включает overlay/скрипты/лицензии, закреплённые strongSwan и OpenSSL,
сгенерированные исходники strongSwan 6.0.3, Conscrypt 2.7.0 и BoringSSL
7c1efd8d6ffb36a57feba44e8c73cf674801f3cb, а также исходники runtime-зависимостей.
`dependency-lock.json` фиксирует фактические версии и хеши артефактов.
Лицензии и notices в `licenses/dependencies`, POM содержат сведения об авторах
и лицензиях; полные исходные notices также сохраняются в архивах зависимостей.

Beta предназначена для контролируемого расширения группы. Нельзя заменять
результатами эмулятора проверку конкретного Samsung/Honor/оператора или объявлять
часовой тест ночным. Фактическая матрица и исключения публикуются с каждым APK.

## Изменения хранилища в code 12

Сертификат и зашифрованный токен записываются вместе в AtomicFile `device.json`.
Старый `token.sealed` читается до успешного повторного подтверждения/продления.
После успешной миграции старый файл удаляется. Токен по-прежнему шифруется ключом
AndroidKeyStore; открытого токена в JSON нет. Если сохранённый токен недоступен,
редактор позволяет ввести его заново. Потеря ключа устройства создаёт новую identity.

Неотправленный диагностический отчёт связан с identity в локальном хранилище.
Эта локальная привязка удаляется перед отправкой. Отчёт другого доступа или старый
отчёт без привязки автоматически не пересылается; требуется новая диагностика.
