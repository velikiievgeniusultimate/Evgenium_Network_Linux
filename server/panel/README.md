# Панель владельца Evgenium Network

Панель работает на StarFive; публикация через отдельный Cloudflare Tunnel.
Адрес текущего развёртывания:

```text
https://panel.velikiievgenius.com
```

## Возможности и ограничения

- Пароль (14–256 символов, scrypt) и Google Authenticator обязательны при каждом входе. Повторное использование кода отклоняется.
- Одна запись пользователя и один токен для всех его устройств; действующий issuer допускает 12 устройств. Панель не меняет этот лимит. Повторное имя после нормализации запрещено; установить, что разные имена принадлежат одному человеку, должен владелец.
- Токены новых пользователей зашифрованы в отдельном root-хранилище и показываются только по запросу владельца. Старые токены issuer хранил только в виде хеша: для их показа потребуется импорт существующей копии, без смены токена и сертификатов.
- Список устройств и текущие SA strongSwan; недоступность измерения отображается как неизвестное состояние. Одновременные подключения десяти реальных устройств пока не проверены.
- Состояние служб, ресурсы и время последнего измерения канала с Эстонией. История падений и полная диагностика — следующий этап.
- Журнал входов и операций без секретов. Web-интерфейс не имеет команд перезапуска VPN, изменения маршрутов или чтения CA.

## Установка приложения

На Debian StarFive с уже установленным evgenium-token-issuer:

```bash
sudo bash server/panel/install.sh
```

Скрипт самостоятельно устанавливает Flask, Gunicorn, cryptography, qrcode и их зависимости из системных репозиториев. Повторная установка сохраняет конфигурацию, пароль, TOTP и данные. Перезапускаются только две службы панели.

Приложение слушает исключительно 127.0.0.1:9081. Разрешённый Host записан в /etc/evgenium-panel/config.json; при другом домене измените allowed_hosts до публикации.

## Публикация

В Cloudflare создайте remotely-managed Tunnel и proxied CNAME домена на UUID.cfargotunnel.com. Ingress: выбранный hostname → unix:/var/lib/evgenium-panel-http/panel.sock, httpHostHeader совпадает с hostname; последнее правило http_status:404. API Token нужен только для настройки DNS/Tunnel, на сервер его помещать не требуется.

На сервер переносится отдельный connector token, файл root:root 0600. Установка отдельной службы:

```bash
sudo bash server/panel/install-tunnel.sh /path/to/cloudflared-riscv64 /root/connector-token
```

Systemd передаёт секрет через LoadCredential; токена нет в командной строке. Служба работает в существующем пространстве evg-link и выходит через Эстонию по TCP 7844; метрики 127.0.0.1:9091 доступны внутри этого пространства. С приложением на StarFive связывается через Unix socket с отдельной группой доступа. Падение межсерверного канала делает сайт недоступным снаружи; это ограничение первой версии. Никаких входящих портов роутера или изменений firewall. Прямые соединения через домашнего провайдера регистрировались как healthy, но возвращали 502/1033; поэтому используются evg-link и HTTP/2.

Текущая нативная сборка: cloudflared 2026.10.1, commit 8e090e5bfa7a53e824fb2d7eb276f8ab08337b80, Go 1.27.2, CGO_ENABLED=0, GOOS=linux, GOARCH=riscv64. SHA256: 8c8ec84a7c34538b16f9864d18826546481ec7c0facedd72b0b49f39f973e322.

На машине со свежим Go и git сборка из официального репозитория:

```bash
git clone --branch 2026.10.1 --depth 1 https://github.com/cloudflare/cloudflared.git
cd cloudflared
# Убедиться, что checkout соответствует указанному выше commit.
CGO_ENABLED=0 GOOS=linux GOARCH=riscv64 go build -mod=readonly -trimpath -ldflags '-s -w -X main.Version=2026.10.1' -o cloudflared-riscv64 ./cmd/cloudflared
```

Сборку лучше выполнять на рабочем компьютере, чтобы не нагружать одноплатник. Автообновление connector отключено; обновлять отдельной проверенной сборкой.

## Первый вход

В течение 24 часов после первичной установки откройте сайт, введите одноразовый ключ из /root/evgenium-panel-bootstrap.txt, отсканируйте QR в Google Authenticator, задайте собственный пароль и введите текущий код. До завершения этого шага токены и данные сети недоступны. После появления владельца ключ настройки перестаёт работать. QR не отправляется сторонним сервисам.

Cookie Secure/HttpOnly/SameSite=Strict; CSRF, проверка Origin/Host, ограничение попыток входа, запрет кеширования. Сессия ограничена 8 часами и 30 минутами отсутствия запросов; открытая панель обновляется раз в 30 секунд. Закрывайте сеанс кнопкой «Выйти» на чужом компьютере. Потерянный Authenticator восстанавливается только администратором через SSH, публичного обхода второго фактора нет.

## Хранилища и резервное копирование

Сохраняйте согласованный root-only backup следующих каталогов (включая ключи шифрования):

- /etc/evgenium-panel — конфигурация и ключ шифрования TOTP;
- /var/lib/evgenium-panel — SQLite, использовать SQLite backup API для копирования работающей БД;
- /var/lib/evgenium-panel-broker — vault.key и зашифрованные токены;
- /var/lib/evgenium-enrollment — действующая база пользователей issuer (копировать под его accounts.lock);
- /etc/evgenium-panel-tunnel — отдельный секрет connector.

Не помещать backup в Git, публичные отчёты или общедоступный web-каталог. Потеря ключа vault не позволяет восстановить текст токенов из хешей issuer.

## Проверка и остановка

```bash
python3 -m unittest discover -s server/panel/tests -v
systemctl status evgenium-panel evgenium-panel-broker evgenium-panel-tunnel
sudo ip netns exec evg-link curl -fsS http://127.0.0.1:9091/ready
sudo systemctl disable --now evgenium-panel-tunnel evgenium-panel evgenium-panel-broker
```

Последняя команда останавливает только сайт. Проверяйте также публичный HTTPS: ready/healthy connector не гарантирует доступности приложения. Без входа /api/dashboard и /api/audit должны возвращать 401. Владелец базы ещё не создан — публичную проверку выдачи реального токена следует проводить после личной привязки Authenticator.
