# Восстановление Evgenium

`encrypted_backup.py` делает согласованный снимок аккаунтов, CA и панели под
блокировками accounts → CA, SQLite копирует Backup API. Снимок шифруется
AES-256-GCM; случайный ключ заворачивается RSA-OAEP-SHA256. На сервере хранится
только публичный ключ шифрования. Требуется python3-cryptography.

В рабочей установке `evgenium-backup.timer` запускает снимок ежедневно около 04:20
по времени сервера. Хранятся семь последних копий; ExecStartPost отправляет копию
на Эстонию с проверкой закреплённого SSH host key. Отдельный SSH-ключ ограничен
forced command `backup_receive.py`, без командной оболочки, туннелей и PTY.
Неуспешная отправка переводит backup.service в failed; проверить через systemctl
и journalctl. Копия на том же сервере не заменяет отдельное хранилище.

Закрытый ключ восстановления хранится только у владельца. Нужна дополнительная
офлайн-копия ключа на отдельном носителе. Восстановление сначала в изолированную
папку: decrypt(), извлечение tar с безопасным фильтром, PRAGMA integrity_check,
проверка accounts.json и соответствия закрытого ключа сертификату CA.

**Не заменять живую базу старым снимком.** Отозванные после снимка сертификаты
могут снова стать действительными. Перед переключением сверить свежие accounts,
CA index и CRL на обоих серверах, восстановить отзывы, проверить блокировку
удалённого клиента и работу сохранённого. При потере этой информации перевыпустить
доступ, а не открывать старую CA вслепую. Оценка RPO текущего расписания — до суток;
RTO полной замены сервера ещё требует отдельной репетиции на запасной машине.
